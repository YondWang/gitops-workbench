# 可配置 Feature 分支回退设计

## 目标

完整发版以 `feature/*` 为代码来源时，允许操作者指定子仓库缺失同名 Feature 分支后的回退分支。该设置同时适用于保存的自动发版任务和单次手动发版；未填写时沿用现有 `release` 回退行为。

## 范围

### 包含

- 自动任务与手动完整发版表单增加“Feature 缺失时回退分支”输入项。
- 自动任务持久化该值；手动发版仅在本次运行中使用该值。
- 仅在请求来源为 `feature/*`、非 SimOS 仓库缺少该 Feature 分支时使用回退分支。
- 后端校验回退分支名，并在需要回退的仓库中校验其存在。
- 发版计划、运行快照和页面解析结果明确显示实际使用的回退分支。

### 不包含

- 修改云盘分类、构建产物上传或 SimOS CI Pipeline。
- 为每个仓库配置不同的回退分支。
- 改变非 Feature 来源（例如 `fix`、`release`）缺失时的失败规则。

## 设计

新增任务字段 `feature_fallback_ref`。`normalize_release_task` 将其规范为合法 Git ref；空值归一为 `release`，因此历史任务文件和缺少该字段的 API 调用维持原有行为。

`resolve_release_plan` 将归一后的值传给 `resolve_full_release_components`。当非 SimOS 仓库缺少请求的 Feature 分支时，解析器使用该值读取提交快照，并将解析类型标记为 `fallback_ref`。如果指定分支在对应仓库不存在，抛出带仓库 ID 与分支名的错误。SimOS 仓库仍必须存在请求的 Feature 分支，不参与回退。

自动任务表单和手动发版表单均提交同名字段；页面解析表把 `fallback_ref` 呈现为“回退 &lt;branch&gt;”。自动任务表单保存后该字段进入任务配置，手动表单的值只传给 `/api/release-runs/manual`。

## 验证

- 对直接解析函数验证：自定义 `bugfix/...` 回退、空值默认 `release`、缺少指定回退分支报错。
- 对计划/手动入口验证：自动任务持久化并传入解析，手动请求传入的值进入任务与运行快照。
- 对静态页面验证：两个入口都有字段，解析展示函数能显示所选分支。
